# МОЩНЫЙ ПРОМТ: SkillQA Pro — автономный тестер скиллов с сертификацией + монетизацией

Создай **SkillQA Pro** — автономную, продаваемую CLI-утилиту, которая качественно тестирует любые скиллы для OpenClaw/агентных систем (структура: папка с SKILL.md + вспомогательные скрипты) по 7 направлениям и выдаёт сертификационный отчёт. Это самостоятельный продукт для авторов скиллов (рынок растёт, а QA-инструмента у них нет — ниша свободна).

---

## ЧАСТЬ 1. НАЗНАЧЕНИЕ И АРХИТЕКТУРА (обязательно)

**Назначение:** проверить произвольный скилл по 7 модулям, выдать вердикт (A/B/C/D) и «сертификат качества», пригодный для публикации на ClawHub/маркетплейсах.

**Жёсткие требования к архитектуре:**
- **Python 3.10+**, совместимость с 3.10/3.11/3.12 (тестировать на всех установленных).
- Один главный файл `skillqa.py` + папка `modules/` с плагинами проверок (по классу на модуль).
- Точка входа: `python3 skillqa.py test <путь_к_скиллу> [опции]`.
- Каждый модуль — класс с `run(ctx) -> Result`: `{module, status: pass|warn|fail, checks:[{name,status,detail}], details, duration_ms}`.
- **Песочница обязательна**: всё исполняемое — во временной папке, с фейковыми env-переменными/токенами, жёстким таймаутом kill. НИКАКОГО реального доступа к сети, секретам, домашним папкам, `rm -rf`, реальным токенам.
- Отчёт: Markdown (человеко-читаемый) + JSON (машиночитаемый для CI/API).
- CLI через `argparse`, сообщения на русском/английском (флаг `--lang ru|en`), читаемый вывод.
- Версия 0.1.0. Отчёты в `./qa_reports/<скилл>/<дата>.md` и `.json`.
- Файл `.qaignore` в скилле (или `--skip module1,module2`) — пропуск отдельных тестов.

## ЧАСТЬ 2. СЕМЬ МОДУЛЕЙ ПРОВЕРКИ (реализовать КАЖДЫЙ)

### 1. Static scan (структура)
- SKILL.md существует, читается, не пустой.
- Валидный YAML-заголовок: name, description, version, tools/allowed-tools, обязательные поля.
- Все пути/файлы, упомянутые в SKILL.md, существуют.
- Нет битых/пустых файлов; размеры разумные.
- Нет «магических» абсолютных путей (портируемость).
- `version` указана и соответствует содержимому.

### 2. Sandbox run (поведение/краши)
- Автообнаружение исполняемых скриптов (*.py, *.sh, *.js).
- Запуск каждого в песочнице: фейковый токен, пустой argv, дефолтные пути.
- Фиксация: exit-code, паника/необработанное исключение, нормальный ли вывод.
- `--help`/`-h` отрабатывает без падения.
- Нет аргументов → падает цивилизованно (понятная ошибка) или фатально? Фатальный краш = fail.

### 3. Log audit (логи)
- Пишет ли скилл логи, куда, есть ли ротация.
- Понятная ошибка: traceback с файл:строкой.
- **Утечка секретов**: сканировать логи/вывод регэкспами (Bearer, token=***, sk-, длинные hex/base64, пароли). Найдено = fail.
- Логи не накапливаются бесконечно (нет append без ротации).

### 4. Novelty (новизна/дублирование)
- Сравнить с библиотекой скиллов (`~/.openclaw/skills`, `~/.openclaw/workspace/skills`, ClawHub при наличии).
- Выявить пересечения по name/description.
- Вердикт: дублирует существующий или добавляет ценность.
- Скилл не «обрезанный»: описание не пустое, есть примеры использования.

### 5. Load test (нагрузка/деградация)
- Прогнать основной скрипт N раз (дефолт 20, флаг `--load N`), замерить время каждого.
- Статистика: min/avg/max/медиана. Растущая деградация (t[N+1] > t[N] в среднем) = fail.
- Утечка памяти: `/usr/bin/time -v` или psutil RSS по серии — стабильный рост = fail.
- Таймаут: зависание дольше лимита (дефолт 15 сек, `--timeout`) → пометить hang, убить.

### 6. Parallel test (гонки/конфликты)
- 5-10 параллельных экземпляров (флаг `--parallel`).
- Нет гонок (конфликт записи в один файл/лог), нет взаимоблокировок.
- Нет уникальных temp-файлов = предупреждение.
- Все процессы завершились за разумное время.

### 7. Compat check (совместимость)
- Определить требуемый Python (shebang, фичи: match/walrus, импорты).
- Проверить зависимости (requirements.txt/imports) — устанавливаются ли.
- Протестировать на установленных 3.10/3.11/3.12.
- Отметить версионозависимые фичи.

## ЧАСТЬ 3. САМОТЕСТИРОВАНИЕ (чтобы SkillQA сам не лагал — критично)

**SkillQA должен уметь тестировать СЕБЯ.** Реализуй встроенный режим:
- `python3 skillqa.py selftest` — прогоняет скилл-тестер на собственном коде и на эталонном «плохом» скилле (намеренно сломанном: крашащийся скрипт, утечка токена в логе, отсутствующий файл, магический путь).
- Проверка: тестер находит ВСЕ намеренно заложенные баги эталонного скилла. Не нашёл хотя бы один = сам тестер не работает → fail.
- Защита от рекурсии/ложных срабатываний на самом себе. Стабильность: 3 прогона подряд дают идентичный результат.
- Основные скрипты утилиты сами проходят static + sandbox (самопроверка целостности).

## ЧАСТЬ 4. МОНЕТИЗАЦИЯ И УПАКОВКА (для продажи)

- **Лицензирование**: свободный режим `--demo` (только статический + отчёт-тизер с 2 модулями), платный `pro` (все 7 + сертификат + JSON для CI). Ключ-лицензия — по образцу ViBo: файл лицензии + привязка к machine-id, ядро-защита (можно .so/запутанный код) по желанию.
- **Способы оплаты** (по образцу ViBo «Модель А»): Telegram Stars + USDT TRC20. Кошелёк USDT пропиши в конфиге-плейсхолдере (значение подставить перед релизом).
- **Вывод отчёта-«сертификата»**: красивый Markdown/HTML с вердиктом по каждому модулю + итоговый балл + логотип/подпись «сертифицировано SkillQA Pro» — то, что автор может показать покупателям своего скилла.
- **README**: установка, использование, список команд, примеры, скриншоты вывода, объяснение модулей и как читать отчёт.
- **Пакет**: собери в zip (skillqa.py + modules/ + README + LICENSE). Приготовь манифест для публикации на ClawHub как платного пакета.

## ЧАСТЬ 5. КРИТЕРИЙ ГОТОВНОСТИ (Definition of Done)

Скилл считается готовым, ТОЛЬКО если:
1. На реальном скилле из `~/.openclaw/skills/` выдаёт осмысленный отчёт по всем 7 модулям без падений самого тестера, <60 сек на статический+песочный прогон.
2. `selftest` находит ВСЕ баги эталонного «плохого» скилла.
3. Сам SkillQA проходит собственный static+sandbox без ошибок.
4. 3 запуска подряд дают стабильный результат (нет рандомных падений).
5. Работает на Python 3.10/3.11/3.12 (или честно сообщает, какие версии протестированы).
6. Демо-режим и pro-режим разделены, лицензия проверяется.
7. README полный, отчёт-сертификат генерируется.

## ЧАСТЬ 6. ЗАДАЧА ДЛЯ ОРКЕСТРА (как проверить и отладить)

Разбей работу на роль-оркестра (multi-agent):
- **Агент-ПРОЕКТИРОВЩИК**: определяет структуру modules/, схемы Result, интерфейсы.
- **Агент-РАЗРАБОТЧИК**: пишет skillqa.py + модули по частям (static → sandbox → log → novelty → load → parallel → compat → selftest → monetization).
- **Агент-ТЕСТИРОВЩИК**: создаёт эталонный «плохой» скилл (3-5 намеренных багов: краш, утечка токена, битый путь, висящий скрипт, магический путь) + эталонный «хороший» скилл; прогоняет selftest и проверяет, что все баги найдены.
- **Агент-ДОКУМЕНТАТОР**: README + отчёт-сертификат + примеры вывода.
- **Агент-УПАКОВЩИК**: собирает zip, готовит манифест ClawHub.

Каждый агент сдаёт результат по чек-листу готовности. Координатор (я) проверяет стыковку модулей. Все правки кода — ТОЛЬКО через G-Stack (правило проекта), никаких ручных правок.
